# Transfer verification

Run `node --test test/*.test.mjs` for permissions, quantities, containers, duplicate requests, inventory rollback, concurrent source changes, and chat failure handling.

In verified Dev1, run `node tools/verify-transfer-foundry.mjs` from Marketplace. This uses isolated Chuck (GM) and Graypes (player) browser sessions, Core's shared runner, and disposable actors/items/chat cards. Player fixture requests target the fresh isolated GM client to leave other GM sessions untouched; ordinary players use Core's active-GM routing. Checks cover tab order/keyboard focus, shared inventory rows, cart minus/plus, whole-stack Group transfers, unowned recipients, denied source ownership, repeated sockets, stale quantities, and chat links. The layout check covers 30% Buy/Sell carts, Source ellipsis, and persisted filter collapse. Core's check covers horizontal tables and long item links. Fixtures are removed afterward. Screenshots cover dark/light themes at 1280px, 520px, and 360px plus an actual chat receipt. Reports are in `test/in-game-reports/transfer*.json`.

For a manual check, open Marketplace as a player. Confirm tabs read Sell → Transfer → Buy → Wishlist. Sell is alphabetical without a Sort By control. In all three carts, add two of an item, decrement to one, increment to two, remove the whole line, and clear multiple lines. Transfer uses Sender and Recipient above the inventory and the same cart structure as Buy and Sell, without extra helper text. Confirm source and target quantities, unchanged transfer currency, and the chat card. In a narrow window, confirm the cart stacks below inventory without horizontal page overflow. Whole container stacks include their nested contents.

In Dev1, import `shopEditorCheck` from `scripts/testing/shop-editor.mjs` as GM and `itemPreviewCheck` from `scripts/testing/item-preview.mjs` as a player, then pass each to Core's `runInGameTests({ checks: [...] })`. The player check opens a restricted transient item through the real native sheet and verifies read-only Observer access and unchanged source permissions. Also click readable and restricted catalog links in Buy, Sell, Transfer, and Wishlist. As GM with a connected player, run `partyMembershipCheck` from `scripts/testing/party-membership.mjs` with the same runner: it creates disposable real documents, transfers as a non-owner member, revokes membership, rejects a stale request, and cleans up its fixtures.

Party regression: as GM, add a player's owned character to a Group without granting that player Group Owner permission. On the player client, confirm the Group is selectable as shopper, payer, and sender; buy, sell, and transfer a disposable item with a connected GM. Confirm each inventory/currency mutation occurs once and source ownership stays unchanged. Remove the character from the Group and repeat: the Group must disappear from shopper/payer/sender choices and old pending requests must fail. Another Group remains a valid recipient. Offline coverage is in `test/party-inventory.test.mjs` and `test/transfer.test.mjs`; live execution remains pending while Demo1 is loaded.

Container regression: pass `containerTransferCheck` from `scripts/testing/transfer.mjs` to Core’s shared runner in Dev1. The fixture fills a backpack with a nested pouch and arrows, adds the filled backpack through the UI, checks the cart total, simulates partial deletion and checks recovery, transfers an overlapping arrow selection, and verifies unique documents, quantities, nested containment, and the receipt. It also transfers contents independently while retaining the container and remaining contents. Disposable actors and messages are removed. The passing report is `test/in-game-reports/transfer-container.json`, verified on Foundry 14.368 / dnd5e 6.0.3. Marketplace's 35 Node checks and Core's design-system check pass.
